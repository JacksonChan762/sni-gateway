# v1.1 Beta — What's New

[English](#english) | [繁體中文](#繁體中文)

Branch: `v1.1-beta` · Implementation commit: `6eafe5c`

## English

### Faster, consistent domain routing

- Replaced sequential suffix regular-expression matching with native nginx hostname maps. Rule conflicts are resolved when generating the configuration.
- Higher-priority rules now win consistently across exact and suffix matches. Equal priorities use the lowest rule ID; duplicate map keys are removed.
- Domain matching is case-insensitive, and HTTP Host ports no longer interfere with matching.
- Added **Publish → Test domain routing** to show the selected rule, priority, exit, and recorded exit status for a domain. The preview includes saved but unpublished changes; it does not test live VPN connectivity.

### Easier exit and stack shutdown

- Added **Exits → Stop All**, with up to four concurrent exit shutdowns and individual failure messages.
- Stopping an exit attempts to stop both its VPN and relay, even if one component fails. Disable and delete operations now report container-removal failures instead of silently ignoring them.
- Exit controls prevent overlapping UI actions and allow retrying a partial stop failure.
- Scheduled restarts now apply only to enabled exits whose recorded status is `running`. Manually stopped exits stay stopped.
- Added `bash scripts/stop.sh` to stop the backend, database-listed dynamic VPN/relay containers, and the remaining Compose services while retaining settings and volumes.
- Added backend signal handling, API shutdown, and cancellation of subscription downloads during shutdown.

### More reliable subscription sync

- Fixed `DOMAIN-SUFFIX` parsing; optional policy columns are supported.
- Normalized domain names, removed duplicate rules, and prevented an overlong line from silently truncating the remaining list. Unsupported entries and invalid domains are skipped.
- Added a 30-second download timeout and explicit rejection of files larger than 10 MiB.
- Replaced per-rule inserts with batches inside one database transaction. A database write failure preserves the previous rules.
- Added checks for subscriptions changed, disabled, or deleted during download. Sync metadata updates no longer overwrite unrelated subscription settings.
- Kept scheduled retries after a failed sync, protected concurrent scheduling, and replaced per-subscription rule-count queries with one grouped query.

### Behavior changes and upgrade notes

- Existing overlaps can route differently: a high-priority suffix rule now overrides a lower-priority exact rule. Review affected domains with **Test domain routing** and **Preview Config** before deployment.
- Manual rule input now validates ASCII/punycode domains. Invalid active rules already stored in the database can block configuration generation until corrected.
- **Stop All** preserves rules, subscriptions, and enabled flags. Stopped routes remain unavailable until their exits are started again; they do not automatically switch to another exit.
- After a full shutdown, run `docker compose up -d` to restore the admin stack, then start the desired exits in the UI. A backend-only restart leaves VPN containers running. Plain `docker compose stop` does not stop dynamically created exits.
- Subscription database changes commit before nginx publication. A publish failure is reported, but does not roll back the committed database rules.
- Deployment and backup procedures are documented in the [application update guide](../UPDATES.md).

### Validation and performance

- Passed backend race tests (`go test -race ./...`), build, and `go vet`.
- Passed real nginx HTTP and TLS SNI routing tests covering priority conflicts, domain boundaries, case handling, and HTTP Host ports.
- Passed frontend TypeScript/production build and eight shutdown/update script tests.
- In the local Go matcher benchmark, 1,000–100,000 rules took approximately **0.37–0.39 µs per lookup**, with **0 bytes and 0 allocations per lookup**. These measurements cover the Go matcher, not end-to-end nginx/VPN throughput.
- Real Docker/VPN deployment and PostgreSQL integration have not been validated in this environment. This is a beta branch.

## 繁體中文

### 更快且一致的網域路由

- 改用 nginx 原生 hostname map，取代逐條後綴正則匹配，並在產生設定時預先解決規則衝突。
- 精確與後綴規則統一依優先級決定結果；優先級相同時採用較小的規則 ID，並移除重複的 map 鍵。
- 網域匹配不分大小寫，HTTP Host 中的連接埠不再影響匹配。
- 新增 **Publish → Test domain routing**，可查看命中的規則、優先級、出口及其記錄狀態。預覽包含已儲存但尚未發布的變更，不會測試實際 VPN 連線。

### 更方便的出口與整套服務關閉操作

- 新增 **Exits → Stop All**，最多同時處理四個出口，並逐項顯示失敗原因。
- 停止出口時會嘗試停止 VPN 與 relay，即使其中一個失敗，仍會處理另一個。停用及刪除操作也會回報容器移除失敗，不再忽略錯誤。
- 出口按鈕會防止介面操作重疊，部分停止失敗時可再次嘗試停止。
- 定時重啟只處理已啟用且記錄狀態為 `running` 的出口；手動停止的出口不會被排程重新啟動。
- 新增 `bash scripts/stop.sh`，依序停止後端、資料庫記錄的動態 VPN／relay 容器，以及其餘 Compose 服務，保留設定與資料卷。
- 後端新增關閉訊號處理、API 關閉流程，以及關閉時取消訂閱下載。

### 更可靠的訂閱同步

- 修正 `DOMAIN-SUFFIX` 解析，支援選用的策略欄位。
- 統一網域格式、移除重複規則，避免單一過長行導致後續清單被悄悄截斷。不支援的項目與無效網域會被略過。
- 加入 30 秒下載逾時，明確拒絕超過 10 MiB 的檔案。
- 改為在同一資料庫交易中分批寫入規則；資料庫寫入失敗時保留原有規則。
- 檢查下載期間訂閱是否被修改、停用或刪除；同步狀態更新不再覆蓋其他訂閱設定。
- 同步失敗後保留排程重試，保護並行排程操作，並以單一分組查詢取得各訂閱規則數量。

### 行為變更與升級注意事項

- 重疊規則的結果可能改變：高優先級後綴規則現在會覆蓋低優先級精確規則。部署前請使用 **Test domain routing** 與 **Preview Config** 檢查受影響的網域。
- 手動規則會驗證 ASCII／punycode 網域。資料庫中既有的無效啟用規則可能導致設定產生失敗，需先修正。
- **Stop All** 保留規則、訂閱及啟用設定。停止的路由須待出口重新啟動後才能使用，不會自動切換至其他出口。
- 完整關閉後，執行 `docker compose up -d` 恢復管理服務，再於介面啟動所需出口。單獨重啟後端會保留 VPN 運行；直接執行 `docker compose stop` 不會停止動態建立的出口。
- 訂閱資料庫交易會先提交，再發布 nginx 設定；若發布失敗，系統會回報錯誤，但不會回復已提交的資料庫規則。
- 部署與備份步驟請參閱[應用程式更新指南（英文）](../UPDATES.md)。

### 驗證與效能

- 通過後端競態測試（`go test -race ./...`）、建置及 `go vet`。
- 通過實際 nginx HTTP 與 TLS SNI 路由測試，涵蓋優先級衝突、網域邊界、大小寫及 HTTP Host 連接埠。
- 通過前端 TypeScript／正式建置，以及八項關閉與更新腳本測試。
- 本機 Go 匹配器基準測試中，1,000–100,000 條規則約為每次查詢 **0.37–0.39 微秒**，每次查詢 **0 bytes、0 次記憶體配置**。此數據僅涵蓋 Go 匹配器，不代表 nginx／VPN 的端到端吞吐量。
- 此環境尚未驗證實際 Docker／VPN 部署及 PostgreSQL 整合；本版本為測試分支。
