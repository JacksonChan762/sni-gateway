# v1.1.2 Beta — What's Updated

[English](#english) | [繁體中文](#繁體中文)

Release branch: `v1.1.2-beta`

## English

### Safer publishing

- Generate the nginx stream and HTTP files from one consistent database snapshot. Validate the written files with `nginx -t` before requesting a reload.
- Restore the previous configuration and backups if validation or reload fails. Backend restarts keep the last written configuration instead of silently replacing it with saved, unpublished rules.
- Show when saved routes differ from the configuration last written for nginx. The Publish page now guides operators through preview, saved-rule checks, and publication. Its checks clearly distinguish rule generation from nginx syntax validation.

### More predictable subscriptions and exits

- Subscription sync applies only rule changes, retaining IDs for unchanged entries and skipping publication for an unchanged list. A previous publication failure is retried on the next sync.
- Exit operations are coordinated per exit, with bounded operation times and a status check that inspects both VPN and relay components and refreshes the public IP.
- API list and statistics queries load less unnecessary data.
- Refreshed compatible frontend dependency versions in the lockfile; the production dependency audit no longer reports high-severity findings.

### Easier operation

- Added `./install.sh` to create private random credentials on first install, check Compose configuration, and wait for healthy services. Existing `.env` credentials are preserved.
- Added `./update.sh` as a root-level entry point to the existing updater. `--check` reports an available revision; `--apply` backs up PostgreSQL, fast-forwards a clean tracking branch, rebuilds, and waits for service health.
- Dashboard and management pages show pending publication, loading errors, and retry actions. Exits can be refreshed with **Check status**. Confirmation dialogs support Escape and keyboard focus handling.

### Upgrade notes and validation

- Use a clean deployment checkout tracking a trusted upstream for `./update.sh`; it refuses local changes and divergent commits. Review [update and recovery guidance](../UPDATES.md) before enabling unattended updates.
- A successful Publish action confirms nginx syntax and a reload request. It does not verify end-to-end VPN connectivity; use the exit status check and a routed-domain test separately.
- Two moderate React Router advisories remain because the available fix requires a major-version upgrade; that migration is outside this beta.
- Passed Go race tests, `go vet`, Go and frontend production builds, real local nginx routing tests, 12 script tests, and browser interaction checks with mocked API responses. Real Docker/PostgreSQL/VPN integration was unavailable in the test environment.

## 繁體中文

### 更安全的發布流程

- 從同一份一致的資料庫快照產生 nginx stream 與 HTTP 設定；寫入後先執行 `nginx -t`，再要求重新載入。
- 驗證或重新載入失敗時，還原原本的設定與備份。後端重新啟動時會保留上次寫入的設定，不會悄悄套用尚未發布的規則。
- 顯示已儲存路由是否與上次寫入 nginx 的設定不同。「發布」頁依序引導預覽、檢查已儲存規則與正式發布，並清楚區分規則產生檢查與 nginx 語法驗證。

### 更穩定的訂閱與出口管理

- 訂閱同步只寫入有變更的規則，未變更項目保留 ID；清單相同時略過發布，上次發布失敗則在下次同步重試。
- 出口操作依個別出口協調並設有逾時；狀態檢查會同時確認 VPN 與 relay，並更新公網 IP。
- API 清單與統計查詢減少不必要的資料載入。
- 更新 lockfile 中相容的前端依賴版本；正式環境依賴稽核已無高風險項目。

### 更容易安裝與操作

- 新增 `./install.sh`：首次安裝產生私密隨機憑證、檢查 Compose 設定，並等待服務健康檢查完成；既有 `.env` 不會被覆蓋。
- 新增根目錄的 `./update.sh`，沿用現有更新機制。`--check` 查詢新版本；`--apply` 備份 PostgreSQL、快轉乾淨的追蹤分支、重新建置並等待服務健康檢查。
- 儀表板與管理頁顯示待發布變更、載入錯誤與重試入口；出口可用 **Check status** 重新查詢。確認視窗支援 Escape 與鍵盤焦點管理。

### 升級注意事項與驗證

- 執行 `./update.sh` 需使用追蹤可信遠端的乾淨部署目錄；本地變更或分支分歧會被拒絕。啟用自動更新前請閱讀[更新與復原指南](../UPDATES.md)。
- 「發布」成功代表 nginx 語法檢查通過，且已送出重新載入要求；實際 VPN 連線仍須另用出口狀態與目標網域測試確認。
- 目前仍有兩項中等風險的 React Router 公告；可用修正需要升級主版本，此次 beta 尚未進行該遷移。
- 已通過 Go 競態測試、`go vet`、Go 與前端正式建置、本機實際 nginx 路由測試、12 項腳本測試，以及使用模擬 API 的瀏覽器互動檢查。測試環境沒有可用的 Docker／PostgreSQL／VPN 整合環境。
